## Target and method

## Defects found and repair evidence

1. **Client replication race.** The first play run failed with `Shell is not a valid member of Folder Workspace.GameForgeSmoke`. The folder arrived before its required child. Client startup now waits for Shell and its ProximityPrompt. Subsequent clean starts emitted the ready message and passed collection. The fixture also explicitly assigns its own respawn location so the original Baseplate spawn does not make the test ambiguous.
2. **Clipped objective/win text.** The original 65-pixel label clipped longer messages; live `TextFits` was false. A 100-pixel label and lower Restart button made the complete carry and win text visible. This runtime experiment was applied to persistent source, rebuilt, and retested; final start/carry/win/reset all reported `TextFits=true`. The final viewport was inspected.
3. **Local test-client transport.** The first long builder command exceeded the terminal's canonical input limit. State inspection proved no partial fixture existed. The owned helper's input handling was corrected before retrying. This was an operator transport defect, not a Studio gameplay pass or a change to the public probe.

The final console contained the fixture ready/collected/won/restarted messages with no fixture error. Three asset-type mismatch warnings for `rbxassetid://203785492` remained. The fixture references no external assets; the warning's cause was not established and it was not hidden or counted as a clean console.

The final server/client source bytes matched the builder before play and after Stop. The stdio client then exited successfully. Studio was left open in Edit mode with the final fixture and original Baseplate objects intact.

## Limits and next use

No two-client behavior, touch/controller test, persistence round trip, external asset import, measured performance, separate-place reconstruction or saved-file reopen is established. The small result supports the core design → build → actual input → inspect → repair → reconstruct workflow only.

To reproduce, open an intended disposable Baseplate, verify the current MCP target, execute the builder in Edit, read it back, then follow [the input checklist](../examples/shell-room/README.md). The builder refuses to overwrite owned names; inspect an existing fixture before replacing it. For broader games, run the brief-specific conditional checks rather than extending this solo result to them.

## Earlier read-only probe work

[The stdlib connection probe](../scripts/probe_studio.py) performs only `initialize` and `tools/list`. It distinguishes initialization with zero tools, partial tool capability, and a full expected capability listing. All reports keep place verification and gameplay verification false. Tool exposure still requires a separate harmless intended-place read and actual playtest.

Run on the selected Studio host:

```sh
python3 scripts/probe_studio.py
```

Use `--server` only for the actual executable supplied by that Studio installation. Exit 0 means expected tool capability names are exposed; exit 2 means they are not established. Neither exit proves a playable prototype. The probe is bounded and closes its own child process; it never starts/stops Studio or mutates a place.

Synthetic protocol tests cover zero/partial/full tools, notifications/noise, pagination, errors, EOF, timeout, malformed tool data and a missing executable. These are executed offline protocol tests, not Studio integration evidence.

The first real run of the new diagnostic also exposed an operator-tool issue: automatic repeated listings could exhaust its shared deadline because Studio's empty list response waits roughly ten seconds. The diagnostic now defaults to one listing; extra retries are explicit. A response timeout remains a failed observation, never proof of an empty or usable place. The corrected real probe returned `initialized_no_tools`, zero tools and exit status 2; [its recorded JSON output](evidence/studio-probe-2026-10-27.json) preserves both place and gameplay verification as false. All 30 offline tests passed (19 package fixtures, 11 synthetic protocol checks); no gameplay test passed in that earlier attempt.
